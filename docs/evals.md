## Live provider runs

Measured **November 18, 2026 (America/Chicago)**; the raw UTC timestamps fall on November 19. Linux x64, kernel `6.12.113+`, Bun 1.4.4, Node v24.22.1. CLI versions: **Codex CLI 0.164.0** with `gpt-6.1-terra`; **Claude Code 2.1.322** with `claude-sonnet-5-5`.

The first-time-user measurements below were made on clean commit `7aa4b26b7e1abbb48f3d29ddb1e89360de5bdd33`. After-fix measurements used the changes atop that commit with `dirty: true`; changes were intentionally left uncommitted. Each provider ran one repetition: four defect cases and two healthy controls, fresh app state and browser session/project per case, no Atlas, 300,000 ms timeout per invocation. After-fix cases ran sequentially within each provider, but provider batches overlapped and local gates shared the host. Durations include harness/browser startup and reporting and are not model-speed comparisons.

**One repetition on a six-case fixture is not a model-quality benchmark.** These runs verify this regression on these CLI/model versions; they do not establish general defect detection, statistical confidence, or broader platform compatibility. Case labels and expected verdicts stay in the scorer, outside the QA prompt.

Before the fix, Codex returned a false PASS on `notes-empty`: it saw an empty list, created a note, and verified that new note instead of the goal's existing notes. Claude left the missing-state and dependent assertions `not_run`, producing INCONCLUSIVE. Both detected the other three defects, and both passed the two healthy controls.

The previous prompt explicitly encouraged creating missing data as setup. The revised generic instructions prohibit unrequested data mutations, require a failed assertion and finding when stated expected state is absent, and reserve `not_run` for dependent or unevaluated checks. The harness also gives validated explicit failures precedence over INCONCLUSIVE; it does not guess missing-state failures from prose or unexecuted checks alone. After the fix, both providers reported the absent existing notes as a failed assertion with a major finding, left opening the nonexistent first note `not_run`, and returned FAIL without creating replacement data. Both healthy controls remained PASS. This is evidence of the observed regression improving, not proof that goal substitution is impossible.

The repair verification used **one Claude pass and one Codex pass** (six invocations each). No second Claude pass was needed. Claude's reported cost includes its reported accounting; Codex cost is unknown, not zero. Input counts retain provider-reported cache accounting as described above. Displayed costs are rounded to seven decimal places. Raw JSON is retained unchanged; its relative report paths identify local evidence directories, not tracked screenshots or transcripts.

## Reproduce or use a live provider

```bash
bun install --frozen-lockfile
bun run browsers:install
bun run eval --repeats 3 --output /tmp/atlas-eval
# After signing into the chosen CLI on a machine with live access:
bun run eval --provider claude --repeats 3 --timeout-ms 300000 --output /tmp/atlas-eval-claude
bun run eval --provider codex --repeats 3 --timeout-ms 300000 --output /tmp/atlas-eval-codex
# Optional: --model <available-model-id>
```

Default is scripted and one repetition. JSON is checkpointed after every run; each relative report path has Markdown, JSON and screenshots beside it. Record the CLI/model version separately when publishing a live result. Budget for up to six provider invocations per repetition. A wall-time timeout is not a dollar cap; configure account-level limits before running.

Only FAIL counts as detection or a false positive. WARNINGS and INCONCLUSIVE remain separately visible and stay in denominators, so a failed provider cannot improve detection by disappearing. The command exits nonzero for any mismatch, warning or inconclusive result; expected bug FAILs do not fail the benchmark. [Scoring tests](../scripts/evals/cases.test.ts) pin these rules. Do not turn this scripted score into a provider certification badge.
